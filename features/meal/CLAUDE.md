# CLAUDE.md — 오늘의 한 끼 (`features/meal`)

이 폴더는 팀원 A가 맡은 "오늘의 한 끼" 서비스다. 저장소 전체 규칙은 루트 `CLAUDE.md`, 요구사항은 `PRD.md` Epic B를 따른다. 이 파일은 이 폴더에서 작업할 때만 적용되는 내용이다. Python 3.14 + Streamlit 기준이다.

## 하는 일

날씨·시간대·주변 식당을 조합해 "지금 먹을 만한 메뉴"를 추천하고, 끼니를 기록한다.

- **B-1 상황 기반 메뉴 추천 (P0, L):** 시간대로 끼니를 판별해 메뉴 3개를 추천한다. 각 추천에 이유 한 줄을 붙이고("비 오는 점심이라 국물이 어울려요"), "다시 추천" 버튼으로 다른 메뉴를 받는다.
- **B-2 주변 식당 연결 (P0, M):** 메뉴를 고르면 카카오 로컬 API로 반경 1km 식당을 거리순 최대 10개 보여준다. 식당명·거리·카테고리와 지도 앱 링크를 표시한다. 0건이면 3km로 넓혀 다시 찾을지 묻는다.
- **B-3 끼니 기록 (P0, M):** 추천 결과나 직접 입력으로 아침/점심/저녁을 기록한다. 같은 끼니는 하루 1회이고 수정·삭제할 수 있다.

## 작업 범위

- 수정해도 되는 곳: `features/meal/`. 이 폴더 밖은 수정하지 않는다.
- `app.py`, `shared/`, `.streamlit/config.toml`은 같은 팀원 A 관리 영역이지만, 다른 서비스가 쓰므로 바꾸기 전에 사용자에게 알린다.
- 다른 서비스 폴더(`reading`, `guest`, `fuel`, `weather`)는 건드리지 않는다. 다른 서비스의 내부 모듈을 직접 import하지 않고, `__init__.py`에서 내보낸 것만 쓴다. 필요한 변경은 담당자에게 요청할 내용으로 정리해 알려준다.

## 병합 계약

- `features/meal/__init__.py`는 `page()`, `ROUTE`, `get_today_summary()` 세 가지만 내보낸다. 내부 모듈은 밖으로 노출하지 않는다.
- `ROUTE = "meal"` (`st.Page`의 `url_path`)
- `get_today_summary()`는 홈 카드용 `{"title", "value", "status"}`를 돌려준다. 오늘 끼니 3칸 진행 상태(예: "2/3")가 들어간다.
- **`page()` 안에서 `st.set_page_config`를 부르지 않는다.** 단독 실행 파일 `dev.py`에서만 부른다. 두 번 부르면 병합 때 오류가 난다.
- 위젯 `key`, `st.session_state` 키, 저장소 이름, 캐시 함수 이름에 `meal_` 접두사를 붙인다. 겹치면 병합 때 `DuplicateWidgetID` 오류가 난다.
- 끼니를 기록하면 `meal_logged { meal_log_id, slot, date }` 이벤트를 발행한다. 팀원 C의 손님이 병합 시 수신한다. `slot`은 `breakfast | lunch | dinner`. 이 이름과 형태는 팀원 C와의 약속이므로 바꾸지 않는다.
- 이벤트를 서비스 사이에 어떻게 전달할지(`st.session_state`, 공유 함수 호출 등)는 아직 정해지지 않았다(PRD 13장). 구현 전에 사용자에게 방식을 확인한다.

## 외부 입력은 목(mock)으로 개발

이 서비스는 다른 서비스 없이 혼자 실행되어야 한다.

- 날씨: 개발 중에는 목 날씨 데이터를 쓴다. 병합 시 팀원 E의 `get_weather(lat, lng)` → `{"temp", "feels_like", "precip", "min", "max", "hourly"}`로 교체한다. 교체가 한 군데에서 끝나도록 날씨를 읽는 코드를 어댑터 한 곳(예: `weather_source.py`)에 모은다.
- 이벤트 수신자(손님)는 아직 없다. 이벤트 발행이 수신자 없이도 에러 없이 동작해야 한다.

## 추천 로직 (룰 기반)

- 입력: 시간대(끼니), 날씨(기온·강수), 메뉴 태그
- 점수 = 시간대 적합도 + 날씨 가중치 − 최근 3일 먹은 메뉴 감점
- 비·눈·한파는 국물류 가중, 폭염은 냉면·샐러드 등 시원한 메뉴 가중
- 가중치와 규칙은 코드에 박지 말고 설정 파일(`toml` 또는 `json`)로 분리한다.
- 메뉴 목록은 직접 큐레이션한 약 100개에 태그(국물/면/밥 등)를 단다. 공공 음식 데이터는 보강용이다.
- 날씨를 못 가져오면 시간대만으로 추천하고 "날씨 정보 없이 추천했어요"를 화면에 표시한다.
- 점수 계산은 Streamlit 없이 테스트할 수 있게 UI 코드와 분리해 순수 함수로 만든다.

## 데이터

- 저장 방식은 미정이다(PRD 13장). 브라우저 저장은 쓰지 않는다. `st.session_state`는 새로고침하면 사라지므로 기록 저장용으로 쓰지 않는다. 저장소 구현을 단정하지 말고, 저장 코드는 `storage.py` 한 파일에 모아 나중에 교체가 쉽게 한다.
- 테이블·키 이름은 `meal_` 접두사를 쓴다(예: `meal_logs`).
- 데이터 구조는 `dataclass`로 정의한다: `MealLog(id, date, slot, menu_name, source, created_at)`. `source`는 `recommend | manual`.
- 같은 날 같은 slot에는 기록이 하나만 있다. 수정은 덮어쓰기이며 새 `meal_log_id`를 만들지 않는다.
- 간식은 추천만 하고 기록하지 않는다.

## 외부 API와 키

- 카카오 로컬 호출 코드는 `features/meal/clients/`에 둔다. 키는 `st.secrets["KAKAO_REST_KEY"]`로만 읽고, 코드·화면·로그·에러 메시지에 출력하지 않는다.
- 호출은 타임아웃 5초(`timeout=5`). 식당 검색 결과는 `st.cache_data`로 캐시한다. 캐시 함수 이름에 `meal_` 접두사를 붙인다.
- 실패하면 식당 목록 영역만 안내 문구와 재시도 버튼을 보여주고 나머지 화면은 정상 동작한다.
- 위치는 검색할 때만 쓰고 저장하지 않는다. Streamlit에는 브라우저 위치 조회 내장 기능이 없어 수동 지역 선택을 기본으로 한다(FR-014). 서드파티 위치 컴포넌트를 쓸지는 미정이므로 도입 전에 사용자에게 확인한다.

## UI

- 색·글꼴·간격은 `.streamlit/config.toml` 테마와 `shared/`의 스타일 헬퍼만 쓴다. 하드코딩과 자체 전역 CSS 주입은 금지한다.
- 서비스 포인트 컬러, 둥근 모서리(16~24px), 리본·별·하트 모티프 등 전체 스타일은 루트 `CLAUDE.md`의 디자인 가이드를 따른다.
- 터치 영역 44px 이상, 본문 대비 4.5:1 이상. 추천 이유처럼 의미 있는 정보를 색에만 의존해 전달하지 않는다.
- 기록은 3탭 이내로 끝낼 수 있게 한다.
- Streamlit은 입력이 바뀔 때마다 스크립트 전체를 다시 실행한다. "다시 추천"을 눌렀을 때 결과가 흔들리지 않도록 추천 결과는 `meal_` 접두사 상태 키에 보관한다.

## 단독 실행

- `features/meal/dev.py`에서 `st.set_page_config`를 부르고 목 날씨로 `page()`를 띄운다. 실행: `streamlit run features/meal/dev.py` (앱 골격이 올라온 뒤 사용). 정확한 파일 구성은 골격이 정해지면 이 파일에 적는다.
- 새 라이브러리를 추가하기 전에 사용자에게 알린다. 의존성은 루트 `requirements.txt` 한 곳에서 버전을 고정한다.

## 완료 기준 (PRD 인수 기준에서 발췌)

- 날씨 API 실패 시에도 추천이 나오고 안내 문구가 보인다.
- 비·눈·한파에는 국물류가, 폭염에는 시원한 메뉴가 먼저 나온다.
- 0건이면 반경 3km 재검색을 묻는다.
- 같은 끼니를 두 번 기록할 수 없다(수정·삭제만 가능).
- 병합 시 목 날씨 교체와 이벤트 연결이 이 폴더 안의 수정만으로 끝난다.
